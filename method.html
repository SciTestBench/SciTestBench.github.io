Task A

Issue Curation

Issue and pull-request pairs from mature GitHub scientific repositories are kept only if they meet all three criteria. Each candidate is then manually reviewed for issue–fix correspondence and scientific relevance.

1

Scientific relevance

The issue concerns scientifically meaningful behavior.

2

No gold test

The closing pull request contains no test changes, which avoids direct test leakage.

3

Executable

Both pre- and post-fix revisions run in a pinned environment.

Task B

Scientific Sanitizer Curation

An LLM first inspects scientific APIs and proposes domain principles that should hold for every valid input. Sanitizers follow a law-first design: the invariant and its precondition are specified before searching for violating inputs, so sanitizers cannot be reverse-engineered around known failures. Generic software checks and invalid or overly narrow preconditions are excluded. Each sanitizer is manually reviewed for scientific validity and numerical soundness.

PreconditionP

Valid input family, e.g. a valid coding sequence.

InvariantI

translate(out) == translate(in)

ObservationO

Compare translated proteins after optimization.

AlarmA

Trigger if the translated proteins differ.
